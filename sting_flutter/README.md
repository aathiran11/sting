# Sting — Phase 1 (Flutter / Android)

This is the Flutter version of Phase 1 (auth + profile flow), so it runs as
a real Android app on your phone and can eventually be published to the
Play Store.

Only the app code (`lib/`, `pubspec.yaml`) is included. The Android/iOS
platform folders (`android/`, `ios/`) are **generated by Flutter itself** —
they contain build tooling (like the Gradle wrapper) that can't be shipped
as plain text, so you'll generate them with one command below. This is the
normal way Flutter projects are set up.

## 1. Install prerequisites (one-time)

- Install **Flutter SDK**: https://docs.flutter.dev/get-started/install/windows
  (the installer includes instructions for PowerShell)
- Install **Android Studio**: https://developer.android.com/studio
  (this gives you the Android SDK + an emulator; you'll also need it to
  accept Android licenses)
- Plug in your Android phone via USB with **Developer Options → USB
  debugging** enabled (Settings → About phone → tap "Build number" 7 times
  to unlock Developer Options), OR use an emulator from Android Studio.

Verify everything's set up:
```powershell
flutter doctor
```
Fix anything it flags with a red X (usually: accept Android licenses with
`flutter doctor --android-licenses`).

## 2. Set up this project

Unzip this folder, open PowerShell inside it:
```powershell
cd path\to\sting_flutter
flutter create .
```
This generates the missing `android/` and `ios/` folders around your
existing code — it will NOT overwrite `lib/` or `pubspec.yaml`.

Then install dependencies:
```powershell
flutter pub get
```

## 3. Run it on your phone

With your phone connected (USB debugging on) or an emulator running:
```powershell
flutter devices
flutter run
```
Pick your device if prompted. The app installs and launches directly on
your phone.

## 4. Build a release APK / App Bundle (for Play Store)

Play Store requires an **App Bundle (.aab)**, signed with your own key.

1. Generate a signing key (one-time, keep this file safe forever — you
   can't update your app later without it):
   ```powershell
   keytool -genkey -v -keystore sting-release-key.jks -keyalg RSA -keysize 2048 -validity 10000 -alias sting
   ```
2. Create `android/key.properties`:
   ```
   storePassword=<your password>
   keyPassword=<your password>
   keyAlias=sting
   storeFile=<full path to sting-release-key.jks>
   ```
3. Follow Flutter's official signing guide to wire that into
   `android/app/build.gradle`:
   https://docs.flutter.dev/deployment/android#signing-the-app
4. Build the bundle:
   ```powershell
   flutter build appbundle
   ```
   Output: `build\app\outputs\bundle\release\app-release.aab`
5. Upload that `.aab` to the **Google Play Console**
   (https://play.google.com/console) — you'll need a one-time $25 Play
   Console developer account, an app listing (name, screenshots,
   description, privacy policy URL), and to fill in Google's content
   rating questionnaire before it can go live.

## Camera permissions (needed for Phase 3 — Unfiltered)

After running `flutter create .`, add camera permission to
`android/app/src/main/AndroidManifest.xml`, just above the
`<application>` tag:
```xml
<uses-permission android:name="android.permission.CAMERA" />
<uses-feature android:name="android.hardware.camera" android:required="true" />
```
Also open `android/app/build.gradle` and make sure `minSdkVersion` is at
least 21 (the `camera` plugin requires it) — set it inside `defaultConfig`:
```
minSdkVersion 21
```
The first time you tap the camera button on your phone, Android will show
the normal "Allow Sting to take pictures?" permission prompt.

## What's in this Phase 1 build

Welcome → Sign up (email/phone) → OTP verify → Username availability
check → Profile setup → Profile view (streak/followers stats, empty
state) → Edit profile → Settings (private account + notifications
toggle, log out) → Login → Forgot password.

All state is in-memory (`lib/app_state.dart`) — no backend yet, so
closing the app resets it. Design tokens (colors/fonts) live in
`lib/theme.dart`; the recurring aperture/camera-iris mark is in
`lib/widgets/aperture.dart`.

## What's in Phase 2 (social graph)

Bottom-nav shell: **Feed** (posts from people you follow, or trending if
you follow no one), **Discover** (search + suggested users by shared
interest), **Profile** (tappable Following count → follow list). Tapping
any user anywhere opens their full profile with a Follow/Following toggle
that updates everywhere live. `lib/data/mock_data.dart` holds the mock
user/post data.

## What's in Phase 3 (Unfiltered camera)

Tap the center camera button (hidden once you've already posted today) to
open `lib/screens/camera_screen.dart` — a live camera preview with **no
gallery/import option anywhere in the flow**. On capture:

- A timestamp overlay is burned into the review screen (`intl` package).
- `lib/services/motion_monitor.dart` samples the accelerometer for the
  seconds before the shutter fires and flags "Live capture verified" vs
  "Low motion — looks static" — a lightweight heuristic against
  photographing a screen or a printed photo, not a guarantee. Real fraud
  prevention (Phase 6 in the roadmap) needs server-side checks too.
- Posting increments your streak once per calendar day
  (`AppState.recordPost`) and the post appears at the top of your Feed
  and on your Profile.

This is all still in-memory — closing the app resets streaks and posts.
Photos are written to the device's temp storage by the `camera` plugin but
aren't uploaded anywhere.
